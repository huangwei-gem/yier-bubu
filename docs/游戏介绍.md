# 游戏介绍

这份文档讲"为什么这么设计"和"数字是怎么来的"。只想看操作和玩法的，去 [README](../README.md)。

---

## 一、立意：把"合作"做成一个物理约束，而不是一句口号

本地双人合作游戏最容易滑向两种形态：两个人各玩各的（并行），或者一个带一个（旁观）。这两种都不需要对方。
这个项目选的做法是把两个人**用一根绳物理地拴在一起**：绳拉直了会互相拽住，掉进坑里绳会兜住，两人同时按跳能跳上一个人绝对够不到的高度。于是"等不等对方""要不要下去兜一次""谁给谁当垫脚"变成每一关都要做的决定，而不是提示语。

绳也因此成为唯一的老师：六个动作（绳子 / 同心跳 / 踩头弹跳 / 沿绳攀爬 / 借绳甩出 / 滑轮吊人）全是同一根绳的不同行为，学会一个就多一把钥匙，而不是多一套操作。

三幕的递进刻意按"约束 → 时间压力 → 空间压力"排：

* **第一幕 · 草原与松林（1-4）**：只有绳本身。尖牙会碎、薄台能穿，都是给绳让路的道具。
* **第二幕 · 峡谷与洞窟（5-8）**：加入"不能停"的元素——会塌的台阶、来回的锯片、必须一直有人站的黄点。绳从"移动工具"变成"责任"。
* **第三幕 · 霜雪与归途（9-12）**：冰面刹不住、传送带一直往前送，把前两幕的动作在压力下重考一遍，最后一关全部串起来。

## 二、硬约束（先定死，再设计）

| 约束 | 后果 |
| --- | --- |
| 一台电脑一副键盘，两个人面对面 | 两人键位必须互不干扰，且能在设置里各自改 |
| 交付形态是一个免安装 exe | 素材必须打进单文件（`embed_pck`），不能依赖任何安装步骤或联网 |
| 包里不放音频文件 | 音效与配乐全部当场合成（`sfx.gd` 里一个十六分音符步进器，峰值约 0.13） |
| 界面不用 `.tres` 主题、不用 Control 皮肤 | 所有画面写在 `_draw()` 里，两种玩法因此看起来像同一个游戏做的 |
| 关卡是数据 | 十二关各是一个 `DATA` 字典，十五局各是一条 `LEVELS` 记录，加一关不改代码 |

## 三、消消乐：为什么是"同一套画片"

开心消消乐那类游戏的观感，一半来自"棋盘上的东西是活的"。这里直接把闯关的角色帧当颜色用——一二、布布本身就是两种"色"，其余是场景里已有的金币、水晶、蘑菇、花、松塔、冰凌、樱花、竹节。于是不需要新画一套素材，两个模式共用 `assets/sprites/` 和 `assets/env/`，选局页和闯关的选关页也是同一套卡片语言。

规则上刻意保留三处"不寻常"：

1. **冰既是收集物也是墙**。冰块不能换、不能消，只能在它旁边消一次敲薄一层（厚冰两下）；同时它不掉落、也不让压在它上面的东西掉落，所以一整列冰能把棋盘劈成两半（第 7 局「冰墙」就是这么来的）。
2. **特殊块在交叉点生成**。四个连成一排出爆破条；L/T 形（横三条配竖三条）在**交点**生成炸弹，而不是随便挑一格；五个连成一排出彩虹球。彩虹球跟任意块换位清一色，两颗对撞清空整盘。
3. **落定后不许留空格**。彩虹清色之后棋盘上没有三连可扫，靠连锁是补不到块的，所以在结算末尾显式检查"有没有已揭开的空格"，有就再补一次重力。这条由 `match3_check` 的不变式守着：每步落定后，除被冰盖住的格外，任何格都不许是空的。

分数：每块基础 60，特殊块被消 240，彩虹球 600；连锁倍率 `1 + 0.5 × (连锁层数 − 1)`，所以第 4 层连锁是 2.5 倍。这是"要不要为了大连锁牺牲眼前一步"的唯一依据。

## 四、十五局的数值是怎么测出来的

门槛不拍脑袋。`tools/match3_check.gd` 里有个贪心机器人：每步枚举所有合法换法，用 `rank_move` 打分（能出特殊块、能连锁、能收目标物加分）再加 0-2 的随机扰动，避免每趟走同一条线。

* 每局固定 6 个种子（`77 + 局号`，棋盘种子 `1000 + 局号×97 + 趟号×13`），所以结果是可复现的；
* 第 1-8 局要求胜率 ≥ 50%，第 9-15 局 ≥ 33%（后面本来就该难）；
* **二星线取"只统计通关局"的分数中位数，三星线取 p90**。用通关局而不是全部局，是因为输掉的分数分布会把门槛拉到"打得烂的人也能过"的位置。

## 五、表现层的几个坑（都留下了防回归）

* **`z_index = -1` 会把棋盘整个藏掉**。消消乐棋盘是 Play 界面的子节点，而 Play 自己在 `_draw()` 里画全屏背景——子节点设负 z 就画到背景底下去了。当时的症状极具欺骗性：模型在跑、分数在涨、探针全绿，屏幕上却一个棋子都没有。修法是给结算层单独加一个"后添加的子 Control"去画，不动任何 z。防回归：截图探针会在棋盘矩形内按 4px 采样、统计量化后的颜色种数，空板只有个位数，有棋子是 70+。
* **棋盘必须待在 HUD 让出来的安全带里**。左右信息栏各占 324px，底部按钮占 78px，所以格子尺寸由 `(vp.x − 696) / 列宽` 和 `(vp.y − 204) / 行高` 取小，再居中到这条带子里。窗口拉伸用的是 `canvas_items + expand`，视口在两个轴上都只会 ≥ 1280×720，所以最扁的窗口下 10×10 也有 58px 的格子，不会挤到信息栏。
* **连锁文字要描边**。它压在奶白色的角色棋子上，纯白字直接看不见，所以画两遍：先暗紫偏移 2px，再白。
* **冰要一眼看出是冰而不是空格**。第一版的冰是一层薄覆盖，读起来像"这里缺了一块"。现在是实心霜面 + 顶边打亮 + 一道斜光 + 层数点（1 层一个点、2 层两个点）。

## 六、自检体系

| 闸门 | 形态 | 覆盖 |
| --- | --- | --- |
| `level_check` | headless | 十二关数据齐全、元素可达、门与压力板对得上 |
| `pages_smoke` | headless | 设置/成就/教学三页 + 音频链路，115 项检查；跑完把存档原样还回去 |
| `match3_check` | headless | 消消乐规则全量 + 十五局数据校验 + 机器人胜率与门槛 |
| `match3_probe` | 窗口 | 39 张截图、合成鼠标按下/拖动/抬起走真输入路径、数像素证明棋子画出来了 |
| `play_probe` | 窗口 | 自动跑完整轮、51 张截图、"过一章只解锁下一章"的解锁链断言 |

另外还有一条**打包后端到端**：把探针场景临时设成主场景、导出一个含 `tools/` 的 exe 跑完整套截图，用来证明发布包里的脚本和贴图真的能渲染（发布包本身是排除 `tools/` 的）。这条只在收尾时跑一次，因为它要动 `project.godot`——跑完立刻还原。

## 七、没做的部分

* 没有联机；只有本地同屏。
* 手柄只做了移动/跳，没有振动反馈；插两个手柄时按 1/2 号分别控一二和布布。
* 成就达成时不弹提示，只在成就页里点亮（不想在闯关途中打断两人对话）。
* 没有存档云备份，也不做多 profile；`user://` 就一份。
* 音乐只有各场景一段循环，没有随进度变化的分层配器。
